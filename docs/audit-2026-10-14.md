# Hum-to-MIDI Music Sketchpad audit — 2026-10-14

**Verdict: not ready for songwriter beta testing yet.** The application builds, starts offscreen, and passes all existing automated suites. The core synthetic workflow works. Five additional diagnostics nevertheless reproduce defects: a horizontal drag with Magnet enabled replaces a canonical pitch, a failed empty take exposes the previous recording, a project loses its non-default MIDI resolution during UI save, the capture adapter splits three-channel audio into invalid blocks, and a failed MIDI overwrite destroys the previous destination contents. The first defect violates the central promise that scale guidance preserves the original idea. Fix these defects and complete real microphone/speaker checks before calling the MVP validated.

This is an audit, not a repair. Application code, dependencies, settings, and existing tests were not changed. The only repository addition is this report. Diagnostics and generated synthetic audio were isolated under `/tmp`; builds and packages are in ignored build directories. Existing uncommitted work was preserved. No recordings were uploaded, credentials accessed, services introduced, builds published, or money spent.

The source of truth was the blueprint supplied in the conversation; `AGENTS.md`; `README.md`; ADRs 0001–0007; recording, pitch, extraction, piano-roll, scale, project and acceptance documents; and the implementation, CMake configuration, and tests. Prior results documents were treated as claims to check. Multiple tracks, chords, accompaniment, beatboxing, and VST3 are deferred and are not counted as missing MVP features.

Status meanings: **PASS** = executed evidence supports the stated behavior; **FAIL** = a reproduced defect; **PARTIAL** = only part is verified or implemented; **MISSING** = absent implementation/artifact; **BLOCKED** = attempted verification could not proceed; **NOT RUN** = not executed. A passing synthetic test does not imply a passing microphone, human-voice, audible-output, or DAW test.

### Actual data flow and consistency

| Stage | Inspected implementation and behavior | Audit conclusion |
|---|---|---|
| Microphone → PCM | `QtAudioCapture` selects a device's reported format; `CaptureIODevice::writeData` normalizes UInt8/Int16/Int32/Float PCM into a fixed scratch buffer. | No pitch analysis, disk I/O or explicit blocking call in this callback. Channel-frame alignment fails for some channel counts (AUD-004). |
| PCM → local recording | `RecordingController` owns a preallocated `BoundedCaptureBuffer`; append copies samples, scans peak and publishes counters atomically. Stop first stops capture, then snapshots the recording outside the callback. | Time limit is 30 s; `duration = sample_count / channels / sample_rate`. Buffer size is duration-bounded but lacks an independent byte ceiling (AUD-007). Prior-take ownership is wrong after an empty failed new session (AUD-002). |
| Channels/rate → analysis | `AudioRecording::monoSamples`/`copyMonoFrames` average channels. Analysis preserves the captured rate. The detector's box-average decimation is internal and retains original frame-start timing. | Stereo averaging and 44.1/48/96 kHz are tested. Opposite-polarity channels can cancel when averaged; no automatic phase correction is claimed. Original audition has explicit output-rate/channel conversion with timing tests; it is not used to retime extraction. |
| Live PCM → diagnostics | `MainWindow::schedulePitchAnalysis` copies up to four available frames; `PitchLabProcessor` invokes `IPitchDetector` on Qt workers; `PitchSmoother` supplies display values. | UI updates are driven by a 33 ms poll; backlog skips old diagnostic windows instead of growing unbounded. Full-window delay, smoothing and UI cadence are distinct from worker runtime. |
| Stopped PCM → raw pitch frames | `PhraseConversionProcessor` runs `PhraseConversionPipeline` with a replaceable `IPitchDetector`; `PitchAnalysisRunner` uses the same YIN implementation as live/fixture paths. | No large model or cloud inference. Raw frames remain separate in `last_conversion_`; conversion uses raw estimates rather than smoothed display pitches. Progress/cancellation are wired. |
| Raw frames → notes | `HysteresisNoteSegmenter` uses 80 ms minimum duration, 35 ms uncertain-gap allowance, 65-cent transition hysteresis and two-frame onset/transition confirmation by default. | Leading/trailing silence and phrase bounds are handled in tested fixtures. Pauses support repeated same-pitch notes. There is no independent reliable articulation/onset detector for uninterrupted same-pitch humming; intent remains ambiguous. |
| Notes → canonical model | `TimedMidiNote` stores MIDI pitch, velocity, channel and double-precision seconds. `NoteEditor::replaceAll` owns the editable phrase; edits validate and use transactional history. | Pitch 0–127, nonzero note-on velocity 1–127, channel 0–15, finite start ≥0 and duration >0. Extraction velocity is fixed at 96. Editing neither reanalyzes nor changes the original PCM. Overlaps are kept and reported, not silently deleted. |
| Canonical → scale projection | `NoteEditor::projectedNotes` derives pitches from canonical notes. `Scale` searches the nearest valid MIDI pitch, preferring the lower pitch on equal distance; invalid below-zero candidates are skipped. | Key selection supplies scale membership, not transposition. Magnet is independent of optional rhythm snapping. Algorithmic projection preserves timing, duration, velocity and channel; AUD-001 is in UI drag construction. |
| Projection → piano roll | `PianoRollWidget` renders `projectedNotes` while committing edits through `NoteEditor`. | Projection → instrument | `QtMidiPlayback` renders `projectedNotes` on a worker through `SimpleSynthRenderer`, then plays PCM through `QAudioSink`. | Note timing is scheduled at sample positions, not UI frames. Playhead reads `processedUSecs`; the UI timer redraws it. Stop/restart/output-change/close paths discard the sink and stale generations. Audible behavior is untested; renderer work itself is not cancellable (AUD-008). |
| Canonical → project | `ProjectFileCodec` schema 1 stores canonical notes/settings; `ProjectFileStore` uses `QSaveFile`. | Projection → MIDI | `MainWindow::exportMidi` passes projected notes and tempo to `MidiTimeline`; `StandardMidiFileExporter` writes format-0 SMF with tempo and note events. | Same projected pitches as instrument playback and visible notes. `ticks = round(seconds × BPM × PPQ / 60)`; default PPQ 480; positive tick duration enforced.
